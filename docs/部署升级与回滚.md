# 部署、升级、备份与回滚

## 1. 发布结构

Docker Compose 默认启动四个服务：

- `frontend`：Nginx 托管 Vue 生产构建，默认映射主机 `8080` 端口。
- `backend`：FastAPI，默认映射主机 `8011` 端口，启动前自动执行 Alembic 迁移。
- `worker`：图片/视频生成 Worker，与后端共享素材卷。
- `mysql`：MySQL 8.4，只在 Compose 内网开放 3306，不占用主机端口。

`8000` 端口不在本项目配置中，保留给 `FlClashCore`。

## 2. 首次 Docker 部署

1. 安装 Docker Engine 及 Compose v2。
2. 复制 `.env.example` 为 `.env`，至少替换：
   - `DATABASE_USER`、`DATABASE_PASSWORD`：应用专用数据库账号。
   - `MYSQL_ROOT_PASSWORD`：与应用账号密码不同的高强度密码。
   - `JWT_SECRET`：至少 32 字符的随机值。
   - `LLM_API_KEY`：仅在使用 DashScope 时填写；稳定演示可使用 `mock`。
3. 确认 `.env` 中 `APP_ENV=production`、`APP_DEBUG=false`。
4. 启动：

```powershell
docker compose up -d --build
docker compose ps
```

5. 检查：

```powershell
Invoke-RestMethod http://127.0.0.1:8011/api/v1/health/live
Invoke-RestMethod http://127.0.0.1:8011/api/v1/health/ready
Invoke-WebRequest http://127.0.0.1:8080/healthz
```

6. 创建首个管理员：

```powershell
docker compose exec backend /app/.venv/bin/python -m backend.scripts.create_admin
```

对外网发布时，应在 Compose 前放置 HTTPS 反向代理/负载均衡，只开放 443，并将 `APP_CORS_ORIGINS` 改为实际域名。

## 3. 升级

1. 阅读新版本发布说明和已知问题。
2. 执行数据库和素材备份。
3. 在预发环境执行 `docker compose build` 和质量门禁。
4. 维护窗口内执行：

```powershell
docker compose pull
docker compose up -d --build
docker compose exec backend /app/.venv/bin/alembic current
docker compose exec backend /app/.venv/bin/alembic check
```

5. 检查后端就绪、前端登录、Worker 日志和一条 Mock 生成任务。

Alembic 由 `backend` 启动命令在 API 对外就绪前执行；迁移失败时容器不会启动 API。

## 4. 备份与恢复

备份数据库：

```powershell
docker compose exec -T mysql sh -c 'exec mysqldump --single-transaction --routines --triggers -u"$MYSQL_USER" -p"$MYSQL_PASSWORD" "$MYSQL_DATABASE"' > ecommerce_ops.sql
```

备份素材卷：

```powershell
docker run --rm -v ecommerce-operations-assistant_asset-storage:/data -v ${PWD}:/backup alpine tar czf /backup/asset-storage.tgz -C /data .
```

恢复会覆盖目标库数据，必须在维护窗口中由管理员确认目标环境后执行：

```powershell
Get-Content .\ecommerce_ops.sql -Raw | docker compose exec -T mysql sh -c 'exec mysql -u"$MYSQL_USER" -p"$MYSQL_PASSWORD" "$MYSQL_DATABASE"'
docker run --rm -v ecommerce-operations-assistant_asset-storage:/data -v ${PWD}:/backup alpine sh -c 'cd /data && tar xzf /backup/asset-storage.tgz'
```

恢复后执行 `alembic current`、`alembic check`、就绪检查及素材文件检查。数据库和素材必须来自同一备份时点。

## 5. 回滚

首选“应用回滚 + 数据保留”：停止新版本，切回上一版镜像/发布包，在旧版支持当前数据库结构时不降级数据库。

若新迁移与旧应用不兼容：

1. 停止前端写入和 Worker。
2. 保留故障环境快照。
3. 使用发布前同时点的 SQL 和素材备份恢复，不对未评审的降级脚本盲目执行。
4. 启动上一版并重做健康、登录、库存和素材抽查。

## 6. 运行监控和故障定位

- API：`/api/v1/health/live`、`/api/v1/health/ready`。
- 请求：使用响应 `X-Request-ID` 对应后端日志。
- Worker：关注任务时间线、错误码、尝试次数、过期锁恢复与超时事件。
- 数据库：发布后确认 Alembic 仅有一个 head，`alembic check` 无漂移。
- 素材：通过素材详情的“检查文件”核对存在性和 SHA-256。
